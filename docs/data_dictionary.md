# Data Dictionary

The project uses the real public M5 Forecasting Accuracy dataset from Kaggle. Raw files are stored locally in `data/raw` after running the download script. These files should not be committed to Git because they are large external data assets.

Dataset source: https://www.kaggle.com/competitions/m5-forecasting-accuracy/data

## Expected Raw Tables

### calendar.csv

Calendar dimension table that maps the M5 relative day format (`d_1`, `d_2`, etc.) to actual calendar dates and retail planning attributes.

Business use:

- Connect sales columns from the wide sales table to real dates.
- Add weekday, month, year, event, and SNAP indicators to demand observations.
- Support time-based validation and calendar feature engineering.

Key fields expected:

- `date`: actual calendar date.
- `wm_yr_wk`: Walmart year-week identifier used to join with weekly prices.
- `weekday`: weekday name.
- `wday`: weekday number.
- `month`: month number.
- `year`: calendar year.
- `d`: M5 day identifier used by sales columns.
- `event_name_1`: primary event name.
- `event_type_1`: primary event type.
- `event_name_2`: secondary event name.
- `event_type_2`: secondary event type.
- `snap_CA`: SNAP eligibility indicator for California.
- `snap_TX`: SNAP eligibility indicator for Texas.
- `snap_WI`: SNAP eligibility indicator for Wisconsin.

### sales_train_validation.csv

Historical daily unit sales table at item-store level. This is the main demand table for the project.

Business use:

- Build the forecasting target: daily units sold.
- Analyze demand by product, department, category, store, and state.
- Create lag and rolling demand features after reshaping to long format.

Key fields expected:

- `id`: unique time series identifier.
- `item_id`: product identifier.
- `dept_id`: department identifier.
- `cat_id`: category identifier.
- `store_id`: store identifier.
- `state_id`: U.S. state identifier.
- `d_1` ... `d_n`: daily unit sales columns.

Initial modeling grain:

- One row per `item_id` and `store_id` in wide format before transformation.
- One row per `item_id`, `store_id`, and date after transformation in later phases.

### sell_prices.csv

Weekly sell price table by product and store.

Business use:

- Add price signals to demand forecasting models.
- Analyze demand sensitivity to price changes.
- Join with calendar through `wm_yr_wk` and with sales through `store_id` and `item_id`.

Key fields expected:

- `store_id`: store identifier.
- `item_id`: product identifier.
- `wm_yr_wk`: Walmart year-week identifier.
- `sell_price`: weekly selling price.

### sample_submission.csv

Kaggle submission template that defines the expected forecast output format for the competition.

Business use:

- Understand the required forecast horizon and submission structure.
- Provide a reference for future forecast output formatting.

Key fields expected:

- `id`: forecast series identifier.
- `F1` ... `F28`: forecast horizon columns.

## Final Modeling Grain

The initial modeling grain will be daily demand by item and store. Aggregated views by category, department, state, and total network will be created for analytics and reporting.

## Phase 3 Processed Analytical Tables

The following Parquet tables are generated by `src/data_understanding.py` in `data/processed`.

### daily_total_demand.parquet

Daily total unit demand across the full Walmart sample.

Columns:

- `d`: M5 day identifier.
- `date`: real calendar date.
- `wm_yr_wk`, `weekday`, `wday`, `month`, `year`: calendar attributes.
- `demand`: total units sold across all item-store series.

### daily_demand_by_state.parquet

Daily total demand by `state_id`, with real calendar dates attached.

### daily_demand_by_store.parquet

Daily total demand by `store_id`, with real calendar dates attached.

### daily_demand_by_category.parquet

Daily total demand by `cat_id`, with real calendar dates attached.

### daily_demand_by_department.parquet

Daily total demand by `dept_id`, with real calendar dates attached.

### product_demand_summary.parquet

Product-level demand summary aggregated across stores.

Important columns:

- `item_id`, `dept_id`, `cat_id`: product hierarchy.
- `total_demand`: total units sold during the historical period.
- `series_count`: number of item-store series represented by the product.
- `avg_series_demand`: average demand per item-store series.
- `zero_demand_days`, `nonzero_demand_days`: aggregate activity indicators.

### series_demand_summary.parquet

Item-store level summary without converting the full daily matrix to long format.

Important columns:

- `id`, `item_id`, `dept_id`, `cat_id`, `store_id`, `state_id`: series identifiers.
- `total_demand`: total units sold by the item-store series.
- `zero_demand_days`: number of historical days with zero demand.
- `nonzero_demand_days`: number of historical days with positive demand.
- `avg_daily_demand`: average daily units sold.

## Phase 4 Demand Segmentation Tables

The following Parquet tables are generated by `src/demand_segmentation.py` in `data/processed`.

### demand_segmentation.parquet

One row per item-store series with demand behavior, volume, variability, and inventory-oriented segments.

Important columns:

- `id`, `item_id`, `store_id`, `state_id`, `cat_id`, `dept_id`: series and hierarchy identifiers.
- `total_demand`, `mean_demand`, `std_demand`: demand magnitude and dispersion.
- `coefficient_of_variation`: total-series coefficient of variation used for XYZ classification.
- `zero_demand_pct`, `positive_demand_days`: intermittency indicators.
- `max_demand`, `median_demand`, `p90_demand`: distribution statistics.
- `first_sale_date`, `last_sale_date`, `active_days`: active sales window.
- `average_demand_interval`: average spacing between positive demand events inside the active window.
- `adi`: Average Demand Interval, calculated as historical days divided by positive-demand days.
- `cv_squared`: squared coefficient of variation calculated on non-zero demand values.
- `demand_pattern`: Syntetos-Boylan class: Smooth, Erratic, Intermittent, or Lumpy.
- `abc_class`: cumulative volume class: A, B, or C.
- `xyz_class`: variability class: X, Y, or Z.
- `abc_xyz_segment`: combined inventory planning segment such as AX, BY, or CZ.

## Phase 5 Baseline Forecasting Tables

### forecast_store_department.parquet

Compact long table with 70 daily store-department demand series. Columns include `unique_id`, `date`, `d`, `d_order`, `demand`, `store_id`, `dept_id`, `item_id`, `demand_pattern`, and `abc_class`.

### forecast_selected_series.parquet

Compact long table for up to 100 selected class-A SKU-store series, prioritized by total demand within each demand pattern.

### selected_series_registry.parquet

Registry of selected SKU-store series, including demand pattern, ABC class, total demand, and selection rank.

### baseline_predictions_store_department.parquet and baseline_predictions_selected_series.parquet

Backtesting predictions with `unique_id`, `cutoff`, `forecast_date`, `horizon`, `model`, `actual`, `prediction`, hierarchy fields, and RMSSE scale.

### baseline_metrics.parquet

Per-series, per-window, per-model metrics: MAE, RMSE, WAPE, RMSSE, sMAPE, MAPE, actual volume, and prediction volume.
## Phase 6 Machine Learning Tables

### ml_store_department_features.parquet

One row per store-department series and date. Includes calendar, event, SNAP, price, lag, rolling, expanding, trend and ratio features. Demand-derived features are shifted to prevent leakage.

### ml_predictions_store_department.parquet

Direct multi-horizon ML predictions with `unique_id`, `cutoff`, `forecast_date`, `horizon`, `model`, `actual`, `prediction`, `store_id`, `dept_id`, and `strategy`.

### ml_metrics.parquet

Per-series, per-window, per-model metrics for ML forecasts.

## Phase 9 - Simulated Inventory Optimization

This phase turns the validated out-of-sample forecast into a simulated inventory planning layer. M5 does not provide real inventory, open orders, logistics costs, supplier lead times, or stockout costs, so all inventory quantities and financial impact estimates are configurable simulation outputs.

Commands:

```powershell
python src\build_official_forecast.py
python src\forecast_uncertainty.py
python src\inventory_simulation.py
python src\inventory_optimization.py
python src\inventory_economic_analysis.py
jupyter notebook notebooks\07_inventory_optimization.ipynb
python -m pytest tests -p no:cacheprovider -q
```

Main outputs:

- `data/processed/official_forecast_store_department.parquet`
- `data/processed/official_forecast_with_uncertainty.parquet`
- `data/processed/inventory_initial_scenarios.parquet`
- `data/processed/inventory_recommendations.parquet`
- `data/processed/inventory_daily_projection.parquet`
- `reports/inventory_optimization_summary.md`
- `reports/executive_inventory_recommendations.md`
